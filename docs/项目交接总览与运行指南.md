# 项目交接总览与运行指南

## 当前问题与后续方向

Glob3R coarse 阶段曾出现 warp 与 conf 可视化变黑、训练无法收敛的问题；修正归一化和匹配方向后，在 ScanNet 上得到初步正确结果。随后完成初步 refinement，单窗口 SfM 中仍出现匹配不足与点云分层；扩展数据并进行大规模训练后，匹配质量明显改善。对应修改与对照过程保存在训练实验文档中。

当前主要训练问题是自采数据从零训练后的匹配覆盖不足。该数据视角间距大，窗口内共视不足，且仅有稀疏或半稠密点云。仅使用稀疏数据的消融复现了同类现象，混合其他数据或不使用稀疏数据时未出现该问题。后续重点是调整共视采样与窗口大小，并混合高质量稠密数据。

另一个方向是 Glob3R head 的时间与空间效率。服务器统计中，单次 reference 的 head 平均耗时约 713 ms，warp refinement 约占 70%。窗口内的 matching tokens、refinement 图像特征，以及 DPT 的 reference 图像分支具有复用空间，相关统计与分析见训练实验文档。

流式研究关注长轨迹漂移、位姿与点图尺度关系，以及 Pi3X 多模态模型改造后的资源收益。后续以官方 ABot-Recon 代码与公开权重建立实验对照，结合本仓库已有观察开展验证。

## 运行与配置

以下命令在仓库根目录执行。依赖见 [requirements.txt](../requirements.txt)；运行前核对数据路径、权重、输出目录和设备设置。

| 任务 | 配置与准备 | 主要产物 |
| --- | --- | --- |
| 数据检查 | [dataset_viz.yaml](../configs/dataset_viz.yaml)：启用数据条目，核对读取入口、帧数、步长与分辨率；索引构建步骤见数据集文档 | `viz/` 下的 RGB-D、重投影图、数据规模与采样耗时 |
| Glob3R 训练 | [coarse](../configs/glob3r_coarse.yaml)、[refinement](../configs/glob3r_refinement.yaml)、[joint](../configs/glob3r_joint.yaml)：核对数据、Pi3 权重、阶段起始权重与 `run_root` | 阶段目录中的日志与 `ckpts/` |
| 全序列 SfM | [sfm/config.yaml](../sfm/config.yaml)：核对图像、标定、模型权重、匹配前端、BA 后端与缓存路径 | 匹配诊断图、稀疏/稠密点云、相机轨迹与轨迹包 |
| 序列评测 | [eval/valid.yaml](../eval/valid.yaml)及 [模型配置](../eval/model)：核对数据、Pi3/Pi3X 与 matching 权重、窗口和输出设置 | 每序列的图像、指标、耗时、实际配置与进度记录 |

```bash
# 数据采样与可视化
python tests/dataset_viz.py

# Glob3R coarse 训练，先填写配置中的数据与权重
accelerate launch --config_file configs/accelerate/ddp.yaml \
  scripts/train_glob3r.py --config-name glob3r_coarse run_root=/path/to/run

# 全序列 SfM
python -m sfm --config sfm/config.yaml

# 序列评测，先填写评测数据与模型配置
accelerate launch --config_file configs/accelerate/ddp.yaml \
  eval/dataset_eval.py --config-name valid
```

refinement、joint 的权重加载方式见 Glob3R 专题；单窗口、GT warp 与 VGGSfM 对照入口见 SfM 专题。集群训练脚本为 [train.sh](../train.sh)，使用时核对环境、项目路径与资源参数。

实验记录关联代码版本、数据范围、实际配置、初始化权重、日志与结果。更换数据或处理规则后重建索引；更换 SfM 图像、权重或前端参数后更新缓存路径。已有训练与效率统计见实验文档，具体实验编号、曲线和 checkpoint 清单继续随交接补齐。
