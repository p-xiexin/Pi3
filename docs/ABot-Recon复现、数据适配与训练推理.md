## 实验设置与问题

Stage I 实验从 Pi3 初始化，将 global attention 权重加载到 causal attention，使用室内外数据与稠密深度监督。仅加载权重后未保留预训练 Pi3 的点云重建效果。数据处理见 [数据集文档](数据集选择、构建与采样规范.md)。

Stage II 使用 A6000 48 GB，受显存限制将序列长度由报告中的 128 帧降为 64 帧，冻结 DINO encoder，关闭 EMA 更新，并将部分中间层权重卸载到 CPU。实验采用了不同的采样帧间隔，较大帧间隔训练的模型轨迹精度更高。

Stage II 仍存在长序列轨迹漂移。增大 pose 损失权重后，漂移减少，同时出现点云尺度异常。目前正在核对点图与位姿平移的单位、归一化和尺度对齐，以及位姿方向与相邻变换的累计顺序。

## 问题思考与个人观点

建议结合以下问题，多参考 [ABot-Recon 报告第 4.1 节及附录 A.1–A.3](https://arxiv.org/html/2608.27529v1)，以及 [官方训练代码与数据适配说明](https://github.com/amap-cvlab/ABot-Recon/tree/train)中的数据策略。其数据选择、时序采样、质量过滤和监督配置，可为分析几何质量、轨迹漂移及尺度问题提供参考。

以下是基于当前实验的判断，具体效果仍需通过数据与监督方式的对照实验验证。

**Q1：自驾数据中的稀疏或半稠密点云，能否支持流式重建训练？**

可以提供部分监督，但不足以独立承担稠密点云结构的学习。几何训练仍应主要依赖仿真数据和高质量稠密标注数据。Pi3 的点云法向损失也有助于改善重建质量；稀疏点云的邻域覆盖有限，法向监督的有效性需要结合深度质量与有效掩码检查。

**Q2：训练中是否还应继续使用自驾数据？**

应继续使用。自驾数据的长序列轨迹监督有利于模型学习大场景中的运动与重建。对于深度稀疏或质量不足的数据，可以关闭点图与法向监督，保留位姿与轨迹监督，将几何学习交给高质量稠密数据。采用这一方式时，仍需确认轨迹标注质量、时序连续性，以及位姿平移与预测几何的尺度关系。

**Q3：缩短训练序列后，增大采样帧间隔是否有助于轨迹学习？**

报告的 Stage II 使用 128 帧序列，本次复现受显存限制降为 64 帧，并尝试了不同的采样帧间隔。实验中，使用较大帧间隔训练的模型表现出更高的轨迹精度。在帧数固定时，较大帧间隔能够覆盖更长的时间范围；这可能增加了训练中的运动跨度，使模型接触到更长范围的轨迹变化。

这一观察支持将帧间隔作为长序列训练的重要配置项，但尚不能说明它能够替代 128 帧训练。增大帧间隔也可能降低相邻采样帧的视野重叠，适用范围需要结合运动速度、场景和轨迹精度继续验证。

**Q4：为什么 ABot-Recon 导出的点云看起来更稀疏？**

官方导出中的过滤与采样策略会减少点数。[PLY 导出脚本](https://github.com/amap-cvlab/ABot-Recon/blob/main/scripts/export_reconstruction_ply.py#L212-L239)默认在图像两轴上以步长 `4` 采样，约保留原像素点数的 `1/16`，剔除非有限值，并在超过默认 500 万点时进一步采样。[推理接口](https://github.com/amap-cvlab/ABot-Recon/blob/main/abot_recon/api.py#L173-L181)还支持置信度过滤，但默认阈值为 `0`，不启用该过滤。因此，使用默认 PLY 导出时，点云稀疏首先来自导出采样，原始预测仍是逐像素点图。

**Q5：基于 Pi3X 的多模态模型做流式改造，能否获得预期的时间与显存收益？**

这个问题来自本次评测：Pi3 推理峰值显存约为 8 GB，Pi3X 约为 23 GB。我们考虑流式方法，主要是为了提高时间和空间效率；[ABot-Recon 报告](https://arxiv.org/html/2608.27529v1)中的低显存结果提供了参考，但它基于 Pi3，而计划改造的是自研的 Pi3X 多模态模型。

两者的点图预测头存在差异：Pi3 / ABot-Recon 使用线性投影与 pixel shuffle 的 [LinearPts3d](https://github.com/amap-cvlab/ABot-Recon/blob/main/abot_recon/modeling/pi3/models/layers/transformer_head.py)，[Pi3X](https://github.com/yyfz/Pi3/blob/main/pi3/models/pi3x.py) 使用卷积与多尺度特征处理的 ConvHead，后者包含上采样过程中的中间特征图开销。但当前评测尚未将各模块的显存拆开统计，不能把 8 GB 与 23 GB 的差距全部归因于预测头。

我的担忧是，流式改造通过限制历史上下文、复用缓存来控制序列增长带来的开销，却仍需执行当前帧的特征提取、多模态处理和几何预测。如果较大的开销来自这些逐帧计算，改造后的显存和速度收益可能达不到预期。因此，需要先确认 Pi3X 多模态模型的主要耗时与显存来源，再评估流式方案能减少其中多少开销；ABot 的资源结果不能直接作为该模型的预期值。

**Q6：为什么 Pi3 与 ABot-Recon 在本次评测中的推理时间相当？**

本次评测中，Pi3 和 ABot-Recon 均未使用 cuRoPE 与 FlashInfer，观察到两者推理耗时相当。当前结果尚未体现出流式方法的速度收益。

我的理解是，流式处理主要减少重复处理历史帧的开销，并控制长序列下的计算增长；当前帧的特征提取与预测仍需执行。因此，其收益与序列长度、调用方式和缓存实现有关，不能仅由流式结构保证。官方加速实现可能影响实际耗时，但尚未通过对照确认其在本次评测中的贡献。

这也意味着，在自研模型上做流式改造时，速度提升需要单独验证。后续可在统一输入与计时范围下，对比不同序列长度及加速组件启用前后的耗时，确认收益来自哪里。
