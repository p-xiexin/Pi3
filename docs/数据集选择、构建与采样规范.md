## 数据集与路径

数据管理沿用 Pi3 [2] 的读取格式，各来源保留对应目录与读取器，统一输出 RGB、深度、相机参数和来源标识。交接记录包含数据版本、子集、存放位置、划分及深度和位姿来源。

其他已实现的读取器完成了小规模样本验证，已确认处理与读取逻辑；尚未正式下载全量数据集，也未实际参与训练。

读取器返回逐帧数据，[BaseDataset](../datasets/base/base_dataset.py) 根据深度、内参和 c2w 位姿生成世界点图与有效掩码。RGB 与深度在同一图像坐标中对齐，深度为相机 Z 深度，深度与位姿平移使用同一尺度。相机系采用 OpenCV 约定，裁剪、缩放和去畸变同步更新图像、深度与内参。

规模统计读取 `sequences`（序列列表）、`num_imgs` / `num_image`（序列到帧数的字典），或 `records` 中的帧列表。输出的 `num_sequences`、`num_images` 用于汇总序列数与图像数；耗时统计中的 `num_samples`、`total_seconds`、`mean_seconds`、`samples_seconds` 分别记录采样次数、总耗时、平均耗时和逐次耗时。这些统计输出不参与采样或模型计算；读取器中的序列和帧数结构也可能用于采样，需保持与实际数据一致。

逐帧字典中的 `depth_source`、`pose_source`、`depth_definition`、`pseudo_label` 用于记录几何信息来源与含义，当前流程不依据这些字段改变输入或监督。

## 数据处理与采样

各数据集的官方工具使用范围与本项目处理逻辑如下：

| 数据集 | 官方工具或已有数据 | 本项目实现 |
| --- | --- | --- |
| ScanNet | 使用官方 SensorData 工具将 `.sens` 导出为 RGB、深度、位姿和内参 | 异常帧过滤、索引构建和采样；异常帧脚本的公开参考见 [3] |
| nuScenes | 调用 `nuscenes-devkit` 读取数据表、LiDAR 和标注框，并使用其坐标变换与投影函数 | 局部点云拼接、物体框过滤流程、深度生成、索引与采样 |
| ASE | 调用 `projectaria_tools` 获取标定并进行鱼眼到针孔重采样 | 距离转 Z 深度、轨迹解析、索引与采样 |
| Waymo | 读取官方 Perception 数据格式及已处理文件 | TFRecord 解析、LiDAR 几何转换、深度投影与邻近帧累积、索引与采样 |
| KITTI | 使用官方 Raw 数据和 Depth Completion 深度图 | 标定解析、OXTS 位姿转换、帧关联、索引与采样 |
| ARKitScenes | 使用官方发布的 RGB-D、轨迹与内参 | 时间关联、位姿转换、RGB-D 对齐、索引与采样 |
| BlendedMVS | 使用官方提供的深度、相机参数和视图配对文件 | 文件解析、位姿转换、索引与采样 |
| Hypersim | 使用官方 RGB、HDF5 几何数据与元数据 | 距离转 Z 深度、坐标与单位转换、数据读取与采样 |

Waymo 预处理将各 LiDAR 的有效回波拼接，结合标定与位姿投影到 RGB 图像生成深度。读取时通过 `depth_accumulate` 控制邻近帧累积：将深度反投影为点云，对齐到目标相机后拼接并重新投影，同一像素保留最近深度。

nuScenes 将采样区间及邻近关键帧的 LiDAR 点云变换到 global 坐标系并拼接，再投影到各采样相机生成深度。`map_context` 控制邻近帧范围；启用物体框过滤时，移除标注框内的点。

实现见 [Waymo 读取器](../datasets/waymo_processed_dataset.py)和 [nuScenes 读取器](../datasets/nuscenes_dataset.py)。调整累积范围或投影扩点后，检查深度覆盖与跨帧对齐。

Waymo、nuScenes 和 KITTI 提供 `splat_radius` 深度膨胀参数，用于增加稀疏深度的像素覆盖，减少投影取整造成的空洞。半径 `r` 以裁剪缩放前的像素为单位，将一个有效深度复制到 `(2r+1)×(2r+1)` 邻域，重叠处取最近深度；设为 `0` 时关闭。Waymo 在邻近帧累积后的重新投影中使用该参数。

膨胀区域会被计入有效深度，进而影响点图和重投影检查。半径过大可能将前景深度扩展到背景、模糊物体边界，并扩大噪声或动态物体残影。使用时先以 `0` 检查原始覆盖，再根据需要使用小半径，重点检查深度边界和遮挡区域；膨胀后的覆盖率增加不代表测量数量或几何精度提高。

多视图采样检查视图重叠和重投影对齐；顺序采样检查帧间隔与轨迹连续性。ABot-Recon 数据适配复用 Pi3、Glob3R 的读取器，通过 sequence wrapper 提供顺序采样与短序列折返。采样结果保持输出顺序，`source_frame_id` 用于追溯来源帧。

实现见 [data_sampler.py](../pi3/models/abot_recon/data_sampler.py)。更详细的数据配置与处理策略见 [1] 及官方代码。

新增数据按以下步骤接入：

1. 登记版本、子集、存放位置、数据划分及几何信息来源。
2. 适配 Pi3 读取格式，确认 RGB-D 对齐、深度单位和位姿方向。
3. 配置索引与采样方式，保留场景边界和来源帧标识。
4. 检查多个场景的样本，保存处理参数、可视化结果及异常记录。

## 使用步骤与可视化

1. 构建索引。Waymo、nuScenes、KITTI、ScanNet、ARKitScenes、ASE 和 BlendedMVS 的读取器提供 `main` 入口。先核对入口中的数据根目录、输出路径和相机等设置，再从仓库根目录运行对应模块。

   ScanNet 先运行 [generate_invalid_scannet_list.py](../scripts/generate_invalid_scannet_list.py)，扫描各场景的 `pose/*.txt`，将无法解析为 4×4 矩阵或含 NaN/Inf 的帧号写入 `data/scannet_invalid_list.json`。对应公开脚本见 [3]，当前版本支持命令行指定路径。随后运行索引入口，按该列表排除异常帧：

   ```bash
   python scripts/generate_invalid_scannet_list.py \
     /starmap/nas/workspace/pxx/data/scannet \
     --output data/scannet_invalid_list.json
   python -m datasets.glob3r_scannet_dataset
   ```

   ASE 支持通过命令行指定路径：

   ```bash
   python -m datasets.ase_dataset \
     --data-root /starmap/nas/workspace/pxx/data/ASE \
     --output data/dataset_cache/ase.npy
   ```

2. 配置采样。在 [dataset_viz.yaml](../configs/dataset_viz.yaml) 中启用需要检查的数据集，将 `index_file` 指向生成的索引，并核对数据路径、帧数、步长和分辨率。ADS 和 Riemann 按现有条目分别通过 `obs_path`、`data_root` 读取缓存。`sample_index` 设置起始样本，`num_samples` 设置样本数量。

   ABot-Recon 在父读取器外使用 `ABotReconSequenceWrapper`，各来源的包装配置见 [dataset.yaml](../pi3/models/abot_recon/dataset.yaml)。父读取器设置 `shuffle=false`、`random_sample_thres=0.0`；wrapper 的 `frame_num` 设置最大采样长度，`frame_step_range` 设置步长范围。驾驶序列使用 `forward_only=true`；允许短序列折返时设为 `false`，并核对最短序列筛选设置。父读取器提供 `frame_step` 时，wrapper 会覆盖其步长。

   检查时结合 `source_frame_id` 核对来源帧，保留 wrapper 输出顺序。使用 `tests/dataset_viz.py` 时需适配 wrapper 的规模统计。

3. 检查样本。在仓库根目录运行：

   ```bash
   python tests/dataset_viz.py
   ```

[检查脚本](../tests/dataset_viz.py) 展示 RGB、深度和跨帧重投影，结果写入 `viz/`，包括样本图、数据规模和采样耗时。当前规模统计依赖父读取器属性，使用 ABot wrapper 时需补充统计适配。

检查多个场景的样本，保存对应配置、处理参数和可视化结果。数据目录或筛选规则变化后，重新构建索引并检查样本。
